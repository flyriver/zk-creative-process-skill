zk-creative-process 技能是如何实现的

这个页面把 Markdown 实现文档转换成中文交互版：按架构、安装、运行、产物、校验和维护拆解。核心思想是让脚本负责确定性的文件和视频处理，让 Agent 负责创意判断与分析写作。

没有匹配内容。请尝试搜索脚本名、文件名、模式名或安装参数。

总体架构

技能被刻意拆成 Agent 指令层和脚本执行层。

Agent 指令层

负责判断什么时候使用技能、选择 `single` 或 `mix`、读取脚本生成的资料，并把骨架 Markdown 替换成创意分析。

SKILL.md 路由规则 写作要求

脚本执行层

负责创建目录、复制视频、探测元数据、抽帧、生成接触表、写入 manifest，并校验产物是否完整。

技能包

三个 Agent 使用同一个技能名，但安装源和默认路径不同。

Codex

skills/zk-creative-process/

  • 包含 Codex 版 SKILL.md
  • 包含 agents/openai.yaml
  • 源包内直接带 PowerShell 脚本

Cursor

skills/zk-creative-process-cursor/

  • 安装后名称仍是 zk-creative-process
  • 路径指向 ~/.cursor/skills/...
  • 安装时注入 bash runtime

WorkBuddy

skills/zk-creative-process-workbuddy/

  • 与 Cursor 包结构接近
  • 路径指向 ~/.workbuddy/skills/...
  • 安装时注入 bash runtime

安装逻辑

安装器默认不覆盖已有技能，必须显式选择备份或替换。

bash scripts/install-skill.sh --agent codex
bash scripts/install-skill.sh --agent cursor
bash scripts/install-skill.sh --agent workbuddy
  1. 要求传入 --agent。
  2. 根据 Agent 选择源包：Codex、Cursor 或 WorkBuddy。
  3. 确定安装根目录：~/.codex/skills、~/.cursor/skills 或 ~/.workbuddy/skills。
  4. 复制源包到 <skills-dir>/zk-creative-process。
  5. 从仓库根 scripts/ 复制 bash runtime 到已安装技能的 scripts/。
  6. 对 bash 脚本执行 chmod +x。
--backup 备份旧版本 --force 替换旧版本 --project 仅 Cursor 支持 
.\scripts\install-skill.ps1
.\scripts\install-skill.ps1 -Backup
.\scripts\install-skill.ps1 -Force
  1. 解析技能源目录。
  2. 默认安装到 %USERPROFILE%\.codex\skills。
  3. 复制 skills\zk-creative-process 到目标目录。
  4. 复制 runtime 脚本到安装包内。
  5. 如果目标已存在，除非传入 -Backup 或 -Force，否则直接停止。

运行流程

single 和 mix 都是脚本先行、AI 后写。

1. 路由一个参考视频，或未说明多个视频属于同一方向。
2. 编排process-reference-video-phase1 调用核心引擎。
3. 处理复制视频、ffprobe、抽帧、生成接触表。
4. 校验运行材料目录校验，返回 JSON 状态。
5. 写作Agent 读取系统资料并替换输出骨架。
bash scripts/process-reference-video-phase1.sh \
  --video "/path/to/reference.mp4" \
  --slug "short-slug" \
  --name "english-name-中文说明" \
  --base-dir "./creative-materials"
1. 路由两个以上视频被明确说明为同方向、同 hook 或同批次。
2. 建目录创建一个方向级材料文件夹，而不是多个 single 文件夹。
3. 批处理每个视频复制、探测元数据、抽取选帧。
4. 共性资料每个视频一张接触表，共用一个 shared analysis。
5. 写作Agent 产出方向级共性拆解和方向池。
bash scripts/process-reference-videos-mix.sh \
  --videos "/path/a.mp4,/path/b.mp4" \
  --slug "shared-direction" \
  --name "shared-direction-同方向说明" \
  --base-dir "./creative-materials"

文件 作用
video_metadata.json 记录生成时间、视频文件、分辨率、时长、编码、音频和格式信息。mix 模式下是视频数组。
frame-index.json 记录选帧时间戳、接触表位置、每张接触表与源视频的对应关系。
ai-input-pack.md Agent 交接文件：列出需要读取的路径，并重复第一阶段规则。
run-manifest.json 记录本次运行生成的路径和状态，用于复查、调试和后续自动化。
product-brief-产品信息.md 为什么是门禁文件
它是从参考素材映射到用户产品的事实来源。如果文件为空或仍有 TODO，Agent 只能完成参考视频拆解，不能编造产品品类、玩法、素材限制或转化目标。
outputs/ 中的文件什么时候被填充
脚本只写骨架。Agent 必须先读取 ai-input-pack、frame-index、metadata、接触表和 product brief，然后把 TODO 替换为分析内容。

校验与安全

默认保护源文件、安装目录和已生成材料。

校验器检查

  • brief.md 和 product-brief-产品信息.md
  • 系统目录和四个系统文件
  • 至少一张 keyframe contact sheet
  • single 的 original-* 或 mix 的 video-*
  • single 或 mix 对应的输出文件
  • 非系统 Markdown 中残留的 TODO

安全策略

  • 源视频默认复制，不移动。
  • 移动必须显式传 --move 或 -Move。
  • 已有材料文件夹不会被覆盖。
  • 已有技能安装不会静默覆盖。
  • 私有视频和生成物被 .gitignore 排除。

开发维护

扩展原则

  • 确定性操作继续放在脚本中。
  • 人类文件留在材料根目录。
  • 机器复查文件留在系统目录。
  • 保持默认复制源视频。
  • 新增必需产物时，同步更新 runtime 和校验器。
  • 影响行为时同时更新三个 Agent 包。
实现 用途 特点
bash macOS Codex、Cursor、WorkBuddy 使用 Python 片段生成和解析 JSON。
PowerShell Windows Codex 使用 PowerShell 对象和 ConvertTo-Json。
